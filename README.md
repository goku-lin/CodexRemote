# Codex Relay

通过浏览器访问 Windows 电脑上的 Codex，对话、查看执行进度、回答提问和审批。执行电脑运行 Relay 与 Runner；手机、平板或公司电脑只需浏览器。每台执行电脑可以独立运行，分别保存授权和历史。

## 安装使用

普通使用者选择完整 Windows EXE 安装包，不需要安装 Node.js、npm 或编译工具。

1. 在执行任务的 Windows 电脑上安装并登录官方 Codex 桌面端。
2. 获取本项目发布的 `CodexRemote-Setup-<版本>.exe`，双击运行。首次使用选择「首次安装」；已有安装选择默认的「修复已有安装」，使用原目录。
3. 安装完成后点击「打开管理程序」，以后双击桌面「Codex远程」或安装目录的 `CodexRemote.exe`。
4. 在管理程序中点击「启动 Codex + 服务」，然后「打开对话网页」。本机网页默认是 <http://127.0.0.1:4317/>。
5. 手机同一 Wi-Fi 连接：在电脑本机网页左下角「连接手机」中开启局域网，查看地址和配对码。外网连接见下方[手机和笔记本连接（外网）](#手机和笔记本连接外网)。

已经运行的 Codex 任务不会因打开管理程序而重启。若首次安装时桌面尚未接通原生连接，请等待任务结束，正常退出 Codex，再通过管理程序启动一次。首次开启局域网需要 Windows 管理员授权。

## 从源码安装和运行

源码运行和 Windows EXE 构建目前面向 **Windows x64**。准备：

- Node.js 22 或更新版本的官方 Windows x64 发行包，`node` 和 `npm` 可在终端使用。
- Windows PowerShell 5.1，以及包含 C# 编译器的 .NET Framework 4.x。构建使用 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`。
- 安装并登录官方 Codex 桌面端，用于实际执行任务和验证原生桌面连接。只构建 EXE 不需要登录账号。
- 获取本仓库后，终端切换到包含 `package.json` 的项目根目录；安装 npm 依赖时需要联网。

```powershell
node --version
npm --version
npm ci
```

源码方式日常启动可以双击根目录 `启动.cmd`。如果需要先生成本机 `CodexRemote.exe` 和桌面快捷方式，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-manager.ps1
```

然后双击根目录 `CodexRemote.exe`，在管理程序中启动 Codex 和服务。仅调试后台时运行 `npm start`，终端会保持运行，网页访问 <http://127.0.0.1:4317/>；`npm start` 不代替桌面的首次原生连接设置。

修改后端源码后，已运行的后台不会自动加载新代码。在管理程序「重启与恢复」中选择「仅重启远程服务」加载修改，网页会短暂重连；这与重启 Codex 是两个不同操作。开发时若使用前台 `npm start`，可在该终端停止后重新启动。

## 构建 Windows EXE 安装包

在上述 Windows 开发环境和项目根目录中执行：

```powershell
npm ci
npm test
npm run build
```

`npm run build` 生成候选安装包，**不更新当前 OTA 发布清单，不重启服务或 Codex**。构建会编译管理程序和安装器、打包前端与后台、附带 Node.js 运行环境及依赖许可证。无需另外安装 Visual Studio。Node.js 的 `LICENSE` 或 `LICENSE.txt` 必须与 `node.exe` 位于同一目录。

默认输出目录为 `.relay-data/releases/`：

| 产物 | 用途 |
| --- | --- |
| `CodexRemote-Setup-<版本>.exe` | 普通用户双击安装或修复的完整安装器 |
| `connector-<版本>.zip` | 同一版本的便携内容和离线更新包 |
| `candidate-<版本>.json` | 本次候选包的哈希、版本和更新签名清单 |

版本是构建生成的内容标识，完整产物路径会打印在终端。`npm run build` 是面向分发的公开构建，不包含构建电脑的 IP、电脑名或局域网 OTA 来源；安装后的电脑可独立使用，也可从可信 ZIP 手动更新。只有下面的 `npm run package:connector` 会记录本机局域网更新来源。

构建在 `.relay-data/release-signing-key.json` 创建或复用 Ed25519 发布密钥，私钥不进入安装包。后续给同一批局域网设备发布更新应保留原密钥。这里的更新签名不等同于 Windows Authenticode 代码签名。安装包同时包含本项目 MIT 许可证、依赖声明，以及已打包 MPL 依赖的对应源码 ZIP。

### 验证构建产物

完整原生集成和安装包验证需要这台 Windows 电脑已安装 Codex 桌面端。生成候选包后，在同一 PowerShell 窗口执行：

```powershell
$candidate = Get-ChildItem .\.relay-data\releases\candidate-*.json |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
$env:CODEX_RELAY_RELEASE_CHECK_MANIFEST = $candidate.FullName
npm run test:package
Remove-Item Env:CODEX_RELAY_RELEASE_CHECK_MANIFEST
```

验证会在隔离目录检查 EXE 安装与修复、签名、便携运行和模拟任务，不发送模型请求，不修改桌面快捷方式，不重启正在使用的 Codex。只有确认通过后才把对应 EXE 分发给使用者。

### 发布局域网 OTA 更新

```powershell
npm run package:connector
```

此命令重新构建完整 EXE 和 ZIP，并更新 `.relay-data/releases/latest.json`，使本机 Relay 提供新版更新清单。它与只构建的 `npm run build` 不同。需要 Relay 已运行，并在本机网页开启局域网入口，另一台电脑才能通过同一局域网检查更新；现有客户端会核对首次安装时保存的发布公钥。发布后应验证该次发布包：先移除 `CODEX_RELAY_RELEASE_CHECK_MANIFEST` 环境变量，再运行 `npm run test:package`。

构建产物、发布私钥、`.relay-data`、桌面账号目录和认证文件均不应提交到 Git。本项目采用 [MIT License](LICENSE)，第三方依赖保留各自许可证。项目安全边界见 [SECURITY.md](SECURITY.md)，贡献与测试约定见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 功能与运行方式

两台电脑使用同一套完整的 EXE 管理应用：双击桌面「Codex远程」或安装目录的 `CodexRemote.exe`，打开「启动与服务／插件与执行器／重启与恢复」。窗口关闭不停止服务，不增加监听端口，打开窗口只读取本机状态。安装或修复时运行网页下载的 Windows EXE 安装器；已有安装默认在原目录修复，保留配置、授权和任务。未找到原目录会停止，不会自动另装一套；确实首次使用时明确选择「首次安装」。旧桌面快捷方式备份在 `.manager-backups`。

管理应用可检查连接器发布版本、在安装版执行自动更新、打开对话网页、查看日志和按既有密码流程提交恢复请求。本机工作目录不自动执行 Git 更新，使用「重启与恢复 → 仅重启远程服务」加载本机已有代码；会中断公网的操作在窗口中确认，完整重启还需确认中断全部 Codex 任务。执行器页读取本机 `model-providers.json`，显示 Claude Code、DSH 和 API 路由的程序路径、模型及启用状态；不会显示密钥或把「已配置」当作「已登录／正在运行」。开关只控制后续调用，保留原配置备份，不终止已经开始的任务。新版委派工具每次调用重读配置；首次升级前启动的旧 MCP 进程需重新连接插件，之后开关不需要重启 Codex。各 CLI 的安装、登录和自身升级仍由其工具管理。

另一台电脑的安装、修复和 OTA 均使用发布端已编译的同一份 EXE，无需自行运行脚本或编译。管理程序版本由 `manager.json` 选择，后台版本由 `current.json` 选择，因此修复窗口可以保留正在运行的后台。后续在窗口内检查和安装更新，桌面入口会随更新维护。相同版本的 Node 运行环境在文件系统支持时通过硬链接共享磁盘空间；更新后仅清理由新安装器记录且文件未修改的废弃版本，保留选中版本、运行中版本和一个回退版本。无法核实进程、旧目录没有文件记录或存在用户修改时暂不清理。

## 日常启动

双击桌面的 **Codex远程**，或者项目根目录的 **`启动.cmd`**。它会启动或恢复后台，Codex 尚未打开时从原生连接入口打开桌面，最后打开控制网页。已经运行的 Codex 会保留当前任务；如果桌面尚未接通远程控制，等任务结束并正常退出 Codex，再双击同一个入口。

后端源码在 `src/`，辅助脚本在 `scripts/`，日常使用无需逐个打开。`scripts/发布连接器更新.cmd` 只在发布局域网安装包时使用。日常统一使用根目录的 `启动.cmd`。

## 目录用途

| 位置 | 内容 |
| --- | --- |
| `启动.cmd` | 日常启动入口，桌面快捷方式也指向这里 |
| `src/` | 后端、Runner、原生连接与连接器源码 |
| `public/` | 控制网页与前后端共用的界面规则 |
| `scripts/` | Windows 启动、维护、发布与迁移脚本 |
| `tests/` | 自动测试与验证工具 |
| `docs/` | 问题记录和补充说明 |
| `.relay-data/` | 运行状态、凭据、图片、日志和安装包，不进入 Git |

根目录的 `start.mjs`、`server.mjs`、`runner.mjs` 和 `native-cli-proxy.mjs` 是程序入口，其中后三个只转入 `src/`。保留这些路径使原有后台、桌面代理和命令继续工作；日常双击 `启动.cmd` 即可。旧日志已归档至 `.relay-data/archived-logs/`。

## 两台电脑独立连接（推荐）

手机与公司笔记本只打开浏览器，本地电脑与个人笔记本各自运行 Codex 和本地 Relay。每台执行电脑自己保存任务、发送回执、图片及浏览器授权；独立模式不连接原主电脑，不向它同步事件，也不通过它续期。任意一台执行电脑关机，不影响另一台。无需另租云服务器。

本地电脑继续使用根目录的 `启动.cmd` 和自己的网页地址。个人笔记本先安装并登录 Codex 桌面，从本机「添加电脑」下载新版连接器，解压并运行 `安装连接器.cmd`，回车选择独立连接；不需要填写主电脑地址或电脑连接码。安装目录中：

- `启动.cmd`：与本机一样的日常入口。先检查安装包带好的局域网更新来源，有新版时验证签名并自动更新；来源离线或更新失败时继续使用已有版本。随后启动或恢复连接服务，Codex 未打开时从原生入口打开，再打开控制网页。已运行的桌面继续保留任务；尚未接通远程控制时，等任务结束后正常退出，再双击同一个入口。
- `打开Codex远程连接.cmd`：兼容旧快捷方式，执行与 `启动.cmd` 相同的完整启动流程。
- `打开控制网页.cmd`：启动或恢复本机连接器，再打开控制网页。在「连接手机」查看此电脑的局域网地址及浏览器配对码。
- `配置外网入口.cmd`：此执行电脑安装并登录 Tailscale 后，配置它自己的 HTTPS 私有及公开入口；访问端无需安装 Tailscale，使用公开地址即可。不会覆盖其他程序占用的 Tailscale 端口。公开隧道仍依赖 Tailscale，不保证公司网络能够访问，需实测。
- `更新连接器.cmd`：立即从同一局域网来源检查并更新；更新来源只提供程序包，不提供任务或浏览器授权。没有配置自动来源的旧安装仍提示选择 ZIP。
- `从安装包更新.cmd`：保留手动选择可信 ZIP 的离线更新方式。手动 ZIP 校验检测损坏和路径越界，不验证发布者签名。状态及浏览器授权保留，已有桌面任务继续运行，桌面代理在下次正常启动时更新。

这边改好并验证后，双击 `scripts/发布连接器更新.cmd` 发布一次；那边下次双击 `启动.cmd` 自动获取，无需再复制或解压 ZIP。首次安装即保存发布电脑的局域网 IP、电脑名和 Ed25519 发布公钥，每个来源请求约 2.5 秒超时；电脑名连接失败时会解析其局域网 IPv4 后重试（含解析与重试最多约 7.5 秒），仍逐一验证原发布公钥。失败时显示具体地址和连接、网络拒绝或签名原因；较旧的发布、错误签名、损坏安装包都不能自动安装。更新失败保留原版本，新服务启动失败时选回旧版本；并发更新互斥。仍有任务运行或等待输入、审批时暂缓自动更新，下次空闲时启动再检查。两台未在同一网络、来源关机或不能互访时继续独立运行，下次启动再检查。更新时控制网页可能短暂重连，运行中的 Codex 不重启；原生桥接器的文件随包更新，下次正常关闭桌面后通过 `启动.cmd` 打开才使用新版。发布私钥在本机 `.relay-data/release-signing-key.json`，不进入安装包，请保留该文件。支持自动更新的新包手动安装或更新一次后，后续沿用此流程。

独立服务默认监听 `127.0.0.1:4317`，局域网入口由本机网页开关控制，浏览器首次必须在这台电脑上配对；浏览器授权仍按原规则有效 14 天，过期或撤销后重新配对。不同电脑的凭据不能互用，LAN 与外网采用不同域名时分别配对。局域网 HTTP 传输未加密，限可信网络使用；需要传输加密时使用该电脑自己的 HTTPS 入口。本版没有新增应用层端到端加密。

网页新增「独立电脑入口」。填写各电脑的名称和地址，点选后直接打开对应电脑并保留当前草稿；各电脑的历史和草稿按浏览器来源分别保存。入口名单仅包含名称和地址，保存在浏览器，切换时通过 URL 片段传给目标页面，导入前须核对并确认，不转交 cookie、配对码或消息内容。可下载无脚本的 `Codex电脑入口.html`；保存入口页或分别收藏各电脑的地址，上次访问的电脑离线时仍能选择另一台。本版使用各电脑独立网址切换，不提供脱离所有执行电脑后仍在线的统一云端网页，也不自动扫描局域网。

旧版连接器先按旧方式更新一次，再双击 `切换独立连接.cmd`。切换保留原设备 ID、任务、图片和浏览器授权，替换原主电脑签发的连接器 token，并移除上游地址。默认端口被其他程序占用时停止，不更改连接方式；可在终端运行 `node app/connector-client.mjs independent --home 安装目录 --port 其他端口`（使用当前版本目录的便携 Node）。切换只重启本项目连接器，不重启 Codex 桌面。安装时输入 `2` 可继续采用下面的旧中转模式，原有安装不会被自动切换。

## 同一个手机控制多台 Windows 电脑（旧中转模式）

主电脑运行 Relay，保存原来的手机网址和配对信息。其他电脑只安装连接器并主动连回主电脑，无需在第二台电脑配置端口或公网入口。两台电脑的项目、对话、模型和命令按设备区分，可以同时运行；手机在「连接设备」里切换，切换时保留各自草稿和最近打开的对话。主电脑必须保持开机联网。

### 固定网址与笔记本直连

新版连接器在笔记本上运行独立的本地执行服务，并主动连接主电脑。手机仍打开原来的 HTTPS 网址，配对后自动尝试 WebRTC 加密数据通道；同一 Wi-Fi 或手机热点允许设备互访时，消息、历史、实时输出和审批优先在手机与笔记本之间直接传输。页面显示「直连」或「主电脑中转」，无需换网址。UDP 被防火墙阻挡、热点隔离或浏览器不支持 WebRTC 时继续走主电脑中转；连接失败后每 30 秒检查，失败设备至少间隔 60 秒再尝试。当前不配置 STUN/TURN，主要用于同一网络中的直连，跨网络通过既有主电脑入口转发。

主电脑负责页面入口、设备发现、直连建立与授权续期，仍需保持开机。直连授权每 15 秒续期，45 秒没有有效续期即关闭，浏览器或电脑授权撤销后不能继续续期。此版本不支持主电脑关闭后从同一网址重新打开页面或长期维持直连，也不关闭浏览器的 HTTPS 安全检查。WebRTC 自动使用 UDP 地址，不要求给笔记本配置公网端口；Windows 防火墙仍可能阻止直连，这时显示中转。

两条路径都进入笔记本上同一份 Relay、队列和持久化发送回执；直连写入超时或断线时保留输入并先核对回执，不自动通过中转重复提交。主电脑缓存设备列表与会话摘要，供统一界面显示；笔记本拥有自己的执行状态、已读记录和上传图片。安装包已包含直连依赖，无需在笔记本运行 npm install。已有旧连接器请等任务结束、处理完待发送消息后更新；新连接器需要主电脑后台的 connectorRevision 2。真实手机与第二台电脑的 Wi-Fi/热点连接仍须实机验收。

主电脑双击 `scripts/发布连接器更新.cmd`，或运行 `npm run package:connector`。本机网页「连接设备 → 添加电脑」生成一次性 8 位电脑连接码，并下载安装包。电脑连接码与手机浏览器配对码分开，有效 10 分钟；第二台电脑得到独立凭据，不能冒充其他执行电脑。本机页面可撤销单台电脑的授权。

第二台 Windows 电脑先安装并登录 Codex 桌面，解压全部安装包，双击 `安装连接器.cmd`，填写主电脑网址、连接码、电脑名称和安装目录。包内带 Node.js，无需另装运行环境；安装不修改 Codex 原程序、全局配置、历史或 Goal。等待现有任务结束后正常退出桌面，再双击安装目录的 `打开Codex远程连接.cmd`。连接器、Codex 桌面与主电脑都需保持运行。电脑重启后可双击 `启动连接器.cmd`，桌面仍从原生连接入口打开；目前不设置开机自启。

以后主电脑代码更新后再次双击 `scripts/发布连接器更新.cmd`，第二台电脑双击 `更新连接器.cmd`。更新下载带版本和 SHA-256 校验的包，先验证并准备新版本，再切换连接器。状态与凭据放在安装目录的 `state`，程序放在 `versions`；旧版本保留，下载或准备失败不会切换当前版本。更新只重启连接器，已有桌面任务继续运行；桌面代理在下次正常启动时更新。新版安装包不包含主电脑的 `.relay-data`、token、配对、图片、Git 仓库或机器专用启动脚本。

Codex Relay 是一个本地优先的远程控制界面：浏览器负责显示任务和事件，Runner 运行在真正需要执行 Codex 的电脑上，并通过出站 SSE 连接回 Relay。这样可以在手机或浏览器里查看 Codex 的计划、消息、命令输出、文件变更和审批请求。

### ChatGPT 入口

控制网页左上角的产品选择器可以在 Codex 和 ChatGPT 之间切换。ChatGPT 模式复用当前 Codex 桌面的 `codex-app-tools` 连接读取最近 ChatGPT 对话、加载对话内容并发送后续消息，不访问 `chatgpt.com`，也不改变现有 Relay 端口。只有 Relay 由已接通 Codex 桌面的环境启动、并且 app-tools 可用时，ChatGPT 模式才会显示对话；不可用时页面会保留 Codex 功能并明确提示。

## 启动本机版本

Windows 日常使用双击 `启动.cmd`，也可以运行 `npm run service`。入口会检查后台版本，启动或恢复本项目的 Relay/Runner，再核对已保存的 Tailscale 入口，按需打开 Codex 桌面，最后打开“连接检查”面板。更新后台只重载本项目受监控的服务，不关闭或重启正在工作的 Codex 桌面。已打开的桌面尚未接通原生连接时，等当前任务结束并正常退出 Codex，再双击 `启动.cmd`。

左侧底部的“连接检查”分别显示后台、Runner、桌面、Tailscale 和远程入口状态。“刷新状态”重新检测，“恢复连接”尝试恢复已有服务与转发。后台每 30 秒检查已配置的入口；Windows 服务无响应、已登录连接停在 NoState、原转发缺失时会尝试恢复，恢复失败后至少间隔 60 秒再尝试。需要重新登录、账号与原网址不匹配或端口被其他服务使用时会明确提示，不自动改换账号、网址或覆盖其他服务。手动暂停的 Tailscale 连接只在点击“恢复连接”后恢复。远程设备必须先配对才能使用检查接口。 “恢复连接”执行前会说明可能短暂中断公网访问并请求确认；取消不会发送恢复请求，“刷新状态”只检查。

“连接检查 → 网速检测”仅在点击“检测一次”后，检测当前浏览器与这台服务端之间的响应延迟及上下行有效传输速率（包含请求等待）。每次下载 384 KiB、上传 128 KiB 随机测试数据，另有少量请求及协议开销；不持续测速，不访问第三方测速站，也不调用模型。关闭窗口、切到后台或点击“停止”会取消检测，40 秒后自动超时。结果是小流量短测参考，不代表服务端宽带上限或模型生成速度。检测接口沿用配对和同源校验，禁用缓存和压缩，上传限制大小及等待时间，重复检测受限流保护。

开发和排查期间，公网正常可用时，任何会中断公网访问的操作（关闭或重建 Funnel、停止当前 Relay 等）都必须先向用户说明影响并取得确认。公网已经确认不可用时，直接恢复故障入口，无需再次询问；这不授权重启 Codex 或中断仍正常的连接。用户依赖公司电脑浏览器访问，不能安装 Tailscale；必须保留公网入口，手机的私有入口作为并行备用，不能用它替换或擅自关闭公网。

“连接检查 → 重启与恢复”提供仅重启远程服务、重启 Codex＋远程服务两种操作。先在运行 Codex 的电脑双击项目根目录的「设置重启密码.cmd」（安装版也提供同名入口），在本机终端隐藏输入两次密码（6–128 个字符，支持六位数字）；后台只保存随机盐和 scrypt 哈希。密码只能由本机工具设置或替换，没有网页或 HTTP 密码管理接口，修改无需重启服务。127.0.0.1 也是网页入口；从本机打开“重启与恢复”会显示密码工具的完整路径。恢复窗口单独显示，关闭后返回连接检查。远程操作必须已配对并输入重启密码，完整重启还需明确确认会中断此电脑所有运行中的 Codex 任务。重启由独立进程完成，核对 PID、启动时间和程序路径，通过原生代理重新打开桌面；后台守护进程负责恢复 Relay，网页按请求编号查询结果，重复或断线重试不会再次执行。恢复需实际确认服务、Runner，以及完整重启后的新桌面原生连接；失败不会显示成功。此功能依赖 Relay 仍能收到请求，不能替代电脑断网、休眠或服务完全失去响应时的本机处理。

资源保护针对三处积压：桌面事件队列最多 2,000 项、4 MiB，相邻未发送的文本片段可合并，HTTP 结果不明的片段保持原编号供接收端去重；溢出时从原历史补齐，并重新核对待处理提问。单个 SSE 连接最多缓冲 1 MiB，15 秒仍无法排出时关闭该连接，浏览器重新连接并同步，不自动重发结果不明的输入。浏览器默认最多缓存 8 个对话视图，预加载数量调高时随之扩展（最多 20 个），较早的历史可重新加载，草稿独立保留；长过程组先显示最近 200 项操作，可按需查看较早操作。运行中的过程继续展开显示，用量、连接检查等独立事件不会重绘对话。

左下角“性能设置”可以开启或关闭对话预加载，设置对话数（1–20 个，包含当前对话）、范围（所有已显示项目／仅当前项目）与首次加载回合数（1–20）。默认跨项目预加载 8 条对话，每条读取最近 5 个回合；网页和后台初始预读都遵循这份配置。关闭后不再提前加载其他对话，已缓存内容和运行中任务的同步继续保留。配置保存于当前电脑的 `.relay-data/preferences.json`，连接这台电脑的网页共用；其他独立入口的电脑各自保存，修改立即生效，无需重启 Codex。已手动展开的回合保持原样。近期打开顺序保存在当前浏览器，刷新后继续优先这些对话；后台一次下载一条历史，页面隐藏、设备离线或当前对话正在加载时暂停。预加载只保存历史内容，不渲染图片或播放器，不会把其他对话标为已读；缓存已就绪时切换立即显示，版本改变后补齐。后续同步只传新增或改变的记录，并同步移除、排序和回合状态。切换历史窗口、缓存失效或后台重启后自动读取完整窗口补齐；旧版执行设备继续返回完整历史。服务只缓存增量比对所需的记录编号和指纹，最多 64 份、8 MiB，不为每个版本复制完整历史。

正在处理的回合在底部显示当前命令从开始到现在的实时累计执行时间，点右侧箭头展开命令与输出；并行调用时优先展示仍在运行的命令，不被后来结束的其他命令覆盖。命令运行中每秒更新，超过 10 分钟以黄色提示“运行较久”。当前没有命令执行、模型仍在处理时，底部改为持续显示“本轮已执行”的请求总时间，上一条已结束命令的实际用时保留在展开详情中；展开过程组后，每条命令也显示各自用时。起始时间来自命令开始事件或同一回合、同一命令的原始记录，结束时优先使用原生 durationMs；分页排序用的回合时间不充当命令起点，旧记录缺失真实时间时明确显示未知。计时只更新文字与提示颜色，不增加轮询、不重绘整段消息，也不自动中断任务。

历史文件变化和桌面回合通知继续触发即时读取；备用检查按状态区分，运行中约每 10 秒、已结束约每 60 秒。并发读取同一对话时最多合并保留一次后续读取；连接恢复、主动展开历史和手动同步继续按原路径补齐。新版 Codex 的分页对话通过 `thread/turns/list` 读取当前可见历史，旧日志只用于补充设置和用量。桌面编辑触发 `thread/reverted` 后清理旧的实时输出并重新读取；历史版本检查防止延迟到达的旧结果恢复已撤回的消息。

实时输出按回合更新页面，只解析发生变化的回合，已有历史节点、编辑内容和展开状态继续保留。未改变的 Markdown 文本复用渲染结果，缓存最多 128 条、2 MiB；图片链接每次重新解析，确保切换对话或图片加载完成后使用当前地址。折叠的历史和操作明细继续在展开时加载。

回复中的 Markdown 表格支持列对齐、表头、单元格格式和横向滚动。项目名右侧显示最新回合已完成的对话数量，下方显示运行中与未读数量；失败和中断不计入完成数，统计只使用已有状态，不额外读取所有项目历史。

在 Codex 中归档的对话会从控制网页移除，恢复归档后重新出现。实时通知用于及时同步，后台每 15 秒分页读取完整的未归档列表，补齐漏掉的归档通知；分页失败时保留已有列表。运行状态优先使用当前桌面进程的实时通知和 `thread/read` 元数据，持久化历史里的“已中断”不能覆盖桌面确认仍在运行的回合。后台重启后会核对已有活动回合，运行中约每 10 秒、空闲约每 60 秒重新确认，最多并行读取 4 条元数据；读取失败不会判定回合已停止。历史和旧的活动回合缓存仍用于补充，但不作为运行中的唯一证据，已结束的回合不会被迟到的开始通知重新标为运行中。

侧栏上方可按标题、项目名或目录搜索对话，支持组合关键词；“运行中、未读、等待处理”可与搜索一起使用。搜索和状态筛选覆盖当前电脑的全部可见项目，结果标明项目名；等待处理包含等待回答与审批，未读与侧栏的未读标记一致。筛选只改变列表，点击结果才打开对话；搜索使用已有列表信息，不扫描历史或额外请求后台。结果仍可每次多显示 5 条或显示全部，重置或在搜索框按 Esc 后恢复项目列表及各项目原来的展开数量。

左下角“额度”或输入框里的上下文百分比可以打开用量面板，查看当前执行设备登录账号的额度剩余比例、下次重置时间及返回的积分余额。额度优先通过桌面的 `get_usage_limits` 读取，独立 Runner 使用 `account/rateLimits/read`；按实际窗口时长识别 5 小时和周额度，缺失数据标为“暂未提供”。额度读取在启动、账号变化通知、用户刷新时发生，另有 5 分钟的备用同步；只在数据变化时发布用量事件，不重绘对话。刷新失败保留上次数据并提示。

上下文用量来自当前线程的 `thread/tokenUsage/updated` 或 rollout `token_count`，使用最近一次调用的 `total_tokens / model_context_window` 显示近似占比，不使用整段对话累计 token。压缩后随下一条用量记录更新；未知窗口不估算百分比。重置时间按访问设备的本地时间显示。接口仍需浏览器配对授权。

主电脑从源码运行需要 Node.js 22 或更高版本，以及已经能在终端运行的 `codex` 命令。首次运行或依赖变更后执行 `npm ci`；第二台电脑使用安装包，不需另外安装 Node.js 或 npm 依赖。

```powershell
npm start
```

然后打开 <http://127.0.0.1:4317/>。默认会自动启动本机 Runner，并在连接后同步本机 Codex 的项目、最近线程和历史输出；左侧底部的“同步”按钮可以再次拉取。项目按工作目录归类，每个项目默认展示最近 5 条对话，较早对话仍可展开查看。

`npm start` 通过守护进程启动 Relay，Relay 自动恢复退出的内置 Runner；Codex 子进程退出也会触发 Runner 恢复。恢复间隔从 750ms 逐步增加到 15 秒，运行稳定后恢复初始间隔。正常停止会一起关闭子进程。守护进程本身和电脑需要保持运行，目前没有配置开机启动。直接运行 `node server.mjs` 仅包含 Runner 恢复，不包含 Relay 自身的恢复。

“项目 → 管理”每行左侧勾选显示，右侧手柄拖动排序；手机长按手柄后拖动，拖到列表边缘自动滚动，也可聚焦手柄后用键盘上下方向键调整。点击保存才提交，取消或中断拖动不会提交排序。取消勾选后，Relay 清除该项目缓存的历史，Runner 停止读取这些对话的记录，只保留项目与线程的轻量列表，之后可重新显示。显示选择保存在服务器的 `.relay-data/preferences.json` 中，重启仍有效；项目顺序保存在当前浏览器，隐藏项目不会停止桌面端正在执行的任务。

侧栏仅保留“全部／运行中／待处理”筛选。“待处理”合并未读的完成回复、待回答、待审批和未读的失败对话，计数按对话去重。左上角菜单按钮同步显示待处理数量，全部处理完后隐藏角标。提醒按新完成结果去重，在回合完成、待回答、待审批、失败或中断时触发；发送、排队和引导本身不提醒，旧回合短暂回显也不重复提醒，重连后补上已知对话的新结果。“下一个处理”循环遍历整个队列：未读回复定位并保存已读，待回答或审批定位到相应卡片，查看不会自动回答。提醒设置位于搜索框右侧齿轮，顶部不再显示执行设备选择器，当前电脑连接状态保留在左下角。处理巡览时，对话区提供“下一个处理”和“结束巡览”。

打开对话后默认定位到最新的 5 个完整回合，可每次展开 5 个回合或查看全部。一个回合包含用户输入、中间消息和最终回复：最终回复上方的“上 N 条消息”默认收起，N 统计中间回复、命令、文件修改、浏览器操作、压缩等实际条目；用户输入和最终回复不计入这个数字。展开后按原顺序显示中间文字和合并的操作摘要，摘要再展开才显示具体命令、输入、输出和文件差异。页面更新会保留展开状态、焦点和阅读位置，没有变化的内容不会重绘。

左右栏之间的分隔线可以拖动调整宽度，栏内箭头可以隐藏或恢复侧栏，宽度和隐藏状态会保存在当前浏览器。Relay 默认只监听 `127.0.0.1`，适合先在本机验证流程。

输入框按 Codex 的操作方式提供“＋”、权限菜单、模型弹层、分档强度滑条和发送按钮。点击“选择强度”调整强度，点击弹层里的模型名切换模型，重置按钮恢复所选模型的默认强度。模型列表与支持的强度来自所选设备的 `model/list`，权限遵守设备的 `configRequirements/read` 限制。新建任务先选择目标设备与项目，并显示实际工作目录；服务器以所选项目的目录创建线程，隐藏的项目不能创建任务。

Relay 自己执行的线程先恢复现有线程，再将选项传给 `turn/start`；留空沿用当前设置。Windows 本机安装了 Codex Desktop 时，Runner 优先使用 Desktop 自带的运行程序，避免终端版和桌面版模型列表不一致；也可用 `CODEX_BIN` 指定运行程序。

桌面打开过的线程可能一直由 Desktop 持有写入连接，即使当前回合已经结束。Windows 上可以运行 `npm run connect:desktop` 准备原生连接启动入口，等待桌面当前任务结束并退出 Codex 后，双击项目里的 `scripts/启动原生连接.cmd`（调用 `scripts/打开原生桌面连接.ps1`）重新打开桌面。启动时保留官方 Windows 应用身份，并仅为此次桌面进程设置 `CODEX_CLI_PATH`，避免直接执行 EXE 丢失应用身份后无法使用官方运行框架。应用入口从安装清单解析，实际保留身份后才报告启动成功；失败不回退到普通 EXE 启动。身份仅用于桌面进程，不强制后续命令进程留在应用包环境中。不修改 Codex 安装文件、全局配置、会话历史或 Goal；检测到桌面仍在运行时会停止，不结束任务。准备入口本身不会切换发送路径。桌面升级或移动本项目后可重新运行准备命令。

这个入口也会在 Relay 未运行时启动 `scripts/启动Relay后台.ps1`。后台通过 Windows 的进程管理服务独立启动，避免退出桌面时连带关闭网页服务；日志在 `.relay-data/service-background-out.log` 与 `service-background-error.log`。桌面启动后最多等待约 20 秒，用只读连接检查确认成功才显示“原生连接已接通”。手动运行 `node src/native-desktop-status.mjs` 也可检查，不会发送模型请求。此入口不配置开机自启。

通过这个入口启动后，本机代理转发桌面原有的 stdio 协议，Relay 与桌面共用同一个 Codex app-server 子进程。桌面占用的原对话使用 `turn/start` 提交普通用户输入。运行中点击发送，消息先保存到输入框上方的待发送卡片；点击“引导”才通过 `turn/steer` 追加到当前回合，沿用当前回合设置。卡片提供删除和“撤回编辑”；当前回合成功完成后，按顺序发送下一条。失败、中断和发送结果不确定时保留待发送消息，避免自动继续执行。线程 ID 保持不变，不创建分支。连接通过带随机密钥的本机命名管道开放，不增加公网监听端口。

待发送消息保存在 Relay 后台，刷新和切换浏览器后仍可查看。引导绑定原回合编号，撤回和删除检查消息版本，重复请求使用同一操作编号核对结果。消息已开始提交或结果未确定时不能撤回。撤回时保留图片；输入框已有草稿时追加撤回内容，不覆盖原草稿。

历史用户消息下方提供铅笔入口，在原位置编辑并取消或发送。发送编辑内容需要当前回合已结束，或先使用顶部的中断按钮。Relay 先核对原消息与最新回合，再通过原写入端的 `thread/rollback` 和 `turn/start` 从编辑位置重新生成；该消息之后的对话记录会替换，已经修改的文件不会自动撤销，不调用 Goal 接口。原图片及同一回合中更早的用户输入会保留。回退前保存恢复输入，后续模型请求失败时可继续发送而不再回退一次。当前官方接口将 `thread/rollback` 标记为弃用，接口失效时会显示错误并保留编辑内容。已有桌面代理需在下次从现有原生入口打开桌面时加载编辑能力；后台重载不会自动关闭桌面。

原生代理按可见项目订阅桌面的线程、回合、输出、工具和压缩事件，并将真实提问、命令/文件/权限审批、MCP 信息请求送到 Relay。提问和审批回复原 JSON-RPC 请求编号；桌面与手机同时回答时，只让先到的有效回答送入 Codex。请求过期或回合结束后关闭操作按钮。重新连接会重放尚未处理的请求，并核对已经结束的请求。MCP 普通表单支持 JSON 对象中的基本字段；不支持的复杂字段会明确要求在桌面完成。

2026-10-13 的实时控制更新需要在当前任务结束后通过原生入口重新打开 Codex 一次；代理代码在桌面启动时加载，不会在运行中替换。入口会检查后台版本，自动重载本项目受监控的旧后台，再检查事件与原生提问能力。后台与代理使用旧版本时不会把这些能力显示为已接通。

首次接通原生入口后，连接中断会明确报错并保留输入，不再自动退回任务转发，也不在发送结果不明时重发。今后需要从同一启动入口打开 Codex。尚未接通过原生入口的安装保留旧的 app-tools `send_message_to_thread` 兼容路径；它是任务转发，消息形式与桌面普通用户输入不同，压缩后任务接续的差异见 [问题记录](docs/KNOWN-ISSUES.md)。实际桌面原生输入已验证；压缩后的任务接续仍需验证。

Windows Runner 会沿用已启用的系统 HTTP 代理，解决桌面端能连接、终端进程却直连超时的情况。显式设置的 `HTTPS_PROXY`、`HTTP_PROXY` 或 `ALL_PROXY` 优先，Runner 不修改系统代理设置。

图片可通过“＋”、粘贴或拖入添加，每次最多 5 张、每张 10 MB，支持 PNG、JPEG、WebP、GIF。附件保存在 Relay 的 `.relay-data/uploads` 并传给执行设备；原生桌面连接直接传递图像输入，旧的任务转发连接将图片保存为桌面可以读取的本地附件，再把附件路径与读取请求交给原对话。聊天中的图片（含消息附件、回复内的图片和图片工具结果）默认收起，只显示图片数量；点击“展开”后才加载约 164×132 像素的小缩略图，再点击缩略图或“打开原图”在新标签查看原文件。收起后移除图片元素；刷新网页或切换对话后重新收起，同一对话的新消息更新保留手动展开状态。浏览器懒加载展开区域中的缩略图；本地图片由执行电脑生成最大 640 像素的 WebP 小图，通过已配对的 HTTPS 入口读取，GIF 缩略图使用首帧。外部网址的图片由浏览器直接读取原网址，不保证压缩。MP3/WAV/M4A/OGG 音频、MP4/WebM 视频继续默认显示附件卡片，点击播放才加载媒体。

音视频点击“播放”才创建播放器，支持进度拖动和收起；收到新的对话内容时保留播放器节点。文件按最多 256 KiB 的读取块传输，Range 请求返回对应区段，下载原文件时逐块发送；播放器开始播放后可以按浏览器策略继续预缓冲。当前只提供音视频原文件播放，不自动转码。只允许读取已出现在这条对话中的受支持附件，远程浏览器仍需配对；图片上限 10 MiB，音视频上限 512 MiB。文件大小在首次点击后显示。

图片小图需要执行电脑上的 FFmpeg，可通过 `CODEX_RELAY_FFMPEG` 指定程序路径；缺失或生成失败时显示重试提示，原图仍可手动打开，不自动下载原图。预览缓存最多 64 张、8 MiB，最多同时生成两张，其他请求排队（含生成中的最多 16 张），同一图片请求合并，文件改变后使用新缓存。图片加载失败只更新本张卡片，不反复重绘整个对话。输入框中尚未发送的本地图片继续显示本地预览。当前回合直接显示最新命令、浏览器或文件操作及更新时间，模型容量错误、重试和连接错误会显示在折叠区外。中断按钮位于顶部任务状态旁，连接与同步状态位于左侧底部。

## 手机连接（同一 Wi-Fi）

模型列表里的“管理可选模型”可以取消勾选旧模型，设置保存在 Relay，已配对的手机和电脑共用。已有对话的模型保持原设置，新建任务默认使用勾选列表中的默认模型或第一个模型；至少保留一个模型。

打开或切换到已有对话时，输入框默认选中该对话实际使用的模型和推理强度。手动选择其他模型后，当前对话中后续发送使用所选模型；再次进入对话时重新读取当前设置，旧的浏览器选择不会覆盖它。

失败或中断的回合不在对话中显示“重试／换模型重试”按钮。恢复执行设备后，直接编辑上一条提示词并发送；已进入对话的请求仍保留原始过程和编辑位置。发送编号、断线核对和图片草稿保护继续由后台处理，避免重复提交或覆盖正在编辑的内容。模型容量错误会保留错误说明，Relay 不做无限自动重试。

在 Codex 桌面任务的环境中启动局域网模式，保留原对话续聊通道：

```powershell
npm start
```

电脑浏览器打开 `http://127.0.0.1:4317/`，点击左下角“连接手机 → 开启局域网”。手机连接同一 Wi-Fi，在浏览器打开弹层里的局域网地址，输入 8 位配对码。配对码有效 10 分钟且只能使用一次；配对后的浏览器会记住连接 14 天，服务重启后仍有效。未配对的局域网浏览器不能读取对话、事件、图片或发送任务；Runner 的共享 token 与手机认证分开。配对码输错过多时会限流。

“连接手机”弹层同时管理浏览器授权：配对时可填写设备名称，电脑本机可以改名、查看最近访问和有效期、撤销单个设备或全部设备。授权记录保存在 `.relay-data/browser-devices.json`，重启后保留。撤销立即关闭对应 SSE 连接，后续接口请求被拒绝，浏览器显示重新配对并保留输入草稿；其他设备继续使用。更换配对码只使旧码失效，不撤销已授权的设备。“撤销全部设备”也作废当前配对码。此前的 LAN cookie 下次使用时自动进入列表；全部撤销后，尚未迁移的旧 cookie 也不能重新取得授权。管理入口只允许本机直接访问，已配对的远程设备也不能管理其他授权。

手机左上角的菜单可以切换项目和原对话，也可新建任务。输入框支持模型、强度和图片，手机回车用于换行，点击箭头发送。从后台返回时重新连接事件流并读取最新状态，不自动重发消息。布局适配屏幕高度和底部安全区。电脑需要保持运行；防火墙需要允许同一局域网访问 Relay 的端口。

左侧对话列表默认显示最近 5 条，可点击“再显示 5 条”逐步展开，或“显示全部”一次查看该项目的所有对话。展开后可收回最近 5 条；本次打开网页期间，各项目分别保留自己的展开数量。

正在运行的回合按时间顺序展示中间回复，连续操作默认折叠并汇总实际命令条数；结束后的历史摘要分别显示消息数和命令数。操作的原始输出仍按需展开。桌面 `ImageView` 记录显示为“图片 · N 张”，主动展开后才加载缩略图；图片文件链接和图片详情通过经过配对验证的 Relay 媒体接口读取，本地 `file:///` 路径不会直接交给手机浏览器。

Runner 与已更新的桌面代理发起的 `item/tool/requestUserInput` 提问都能直接提交原请求的 RPC 回答。异步提问使用桌面自身的 `send_user_message_question_reply` 结构化消息，保留问题编号；桌面收到消息后可将对应问题标记为已回答。此前按普通文字转发的历史回答仍显示转发说明，不追溯重发。

选图时只在浏览器本地检查格式、大小及能否解码，并显示预览，不发起上传请求。点击发送后先上传全部图片并确认结果，再将文字和图片编号一起提交给 Codex；图片上传失败时不会先发送文字，输入和图片仍保留供重试。图片上传最多等待 120 秒，确认响应丢失时按原上传编号核对或重试，避免重复保存。Runner 通过经过认证的 HTTP 接口读取图片，不将大图片放入命令事件流。

文字和图片按对话保存为当前浏览器的草稿；本地选图使用 IndexedDB 保存原文件，上传后保存附件编号，刷新或切换对话后仍可恢复。草稿存储依赖浏览器允许本地存储；存储不可用时当前页面仍可发送，重新加载后需要重新选图。每次发送带有唯一编号，HTTP 响应丢失时使用原编号查询或重试；服务在 `.relay-data/deliveries.json` 保存发送结果和相关对话元数据，重启后仍能去重。尚未分发的请求可以恢复，已分发但结果无法确认的请求不会自动重发；界面保留输入并提示核对最新对话，只有用户确认未发送后才解除待确认状态。正常连接每 10 秒发送心跳，心跳只检测连接，不重绘消息；35 秒未收到数据时重建连接。手机回到前台重新读取当前对话，顶部显示断线和执行设备恢复状态。

服务默认只监听 `127.0.0.1`，已配置的 Tailscale 公网 HTTPS 和私有 HTTPS 入口继续转发到本机。需要同一 Wi-Fi 访问或向另一台电脑提供 OTA 更新时，在本机网页左下角「连接手机 → 局域网访问」点击「开启局域网」。首次开启需要 Windows 管理员授权；规则只允许专用网络、本地子网访问当前程序的 Relay TCP 端口，公用和域网络明确阻止。防火墙关闭、没有专用网络或拒绝授权时不会开放入口。已有 Node 阻止规则仍可能阻止局域网访问，请从另一台设备确认。

局域网入口独立监听专用网卡地址，使用「开启局域网／关闭局域网」开关，不设使用时限。开关不重启 Relay、Runner 或 Codex，也不切断现有公网连接。服务重启后恢复默认关闭；网卡消失或检查发现防火墙失效时也会关闭。只有开启期间每 30 秒检查网络状态。配对保护始终生效，远程浏览器不能操作此开关。向其他电脑提供局域网更新前，需要在发布电脑上开启此入口。

提问显示可点击的选项和自由输入，选择后点击“提交回答”。真实 RPC 提问等待提交及完成信号后显示“已回答”；桌面先处理或请求过期时显示“提问已结束”，不再允许重复提交。异步回答提交后显示“回答已送到对话”，收到对应的原生用户消息后显示“已回答”；桌面回答也会同步到网页。提问不被误当成回合结束，计时和后续进度会继续更新。

## 手机和笔记本连接（外网）

使用 [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) 建立仅供私有网络访问的 HTTPS 入口。电脑和访问设备都安装 Tailscale，登录同一账号；手机可以使用流量，笔记本可以使用其他网络。鸿蒙 4.2 可尝试安装 [官方安卓 APK](https://pkgs.tailscale.com/stable/#android)，iPhone 使用 [官方 iOS 安装说明](https://tailscale.com/docs/install/ios)。实际移动端连接仍需在设备上验证。

保持 Relay 和 Codex 桌面运行，在电脑登录 Tailscale 后执行：

```powershell
npm run connect:private
```

脚本先检查运行中的 Relay 是否能区分代理与本机请求，再配置 `tailscale serve --bg --https=443 http://127.0.0.1:4317`。Tailscale 可能需要你在它的官方页面启用 HTTPS；按提示完成后重新执行。已有其他 443 服务或公开 Funnel 配置时会停止，不覆盖它们。

配置成功后，电脑 Relay 左下角“连接手机”优先显示实际 HTTPS 地址。手机和笔记本连接 Tailscale，在浏览器打开该地址并输入电脑生成的 8 位配对码。不同浏览器需分别配对。远程请求即使通过本机代理转发，也不能读取配对码、绕过配对或获取本机权限。HTTPS 配对 cookie 具有 `Secure` 属性；局域网入口继续可用。

私有入口的精确地址保存在 `.relay-data/network.json`，Relay 即时读取它；该文件和配对数据不能提交或分享。此配置使用 Serve，不启用公开 Funnel，也不需要路由器端口转发。Tailscale 服务重启后保留后台 Serve 设置；Relay 本身的开机自启仍未配置。外网浏览器仍使用家中电脑的 Runner，继续同一条对话不需要在笔记本另装 Runner。

### 混合访问：已安装和未安装 Tailscale 的设备

在电脑登录 Tailscale 后执行 `npm run connect:hybrid`。按 Tailscale 官方页面提示启用 HTTPS/Serve 和 Funnel；尚未启用时脚本会输出该页面。脚本先验证远程请求必须配对，且不能读取本机配对码或管理设备，随后配置两个入口：

- 私有 HTTPS `https://电脑名.网络名.ts.net:8443/`：使用 Tailscale Serve，访问设备需连接同一私有网络。
- 浏览器直接访问 `https://电脑名.网络名.ts.net/`：使用 Tailscale Funnel，不要求访问设备安装客户端。公网只能看到配对入口，读取对话、图片和发送消息仍需要 Relay 授权。

两种入口指向同一份 Relay 数据，授权统一由电脑本机管理；相同域名下的浏览器授权在两种 HTTPS 入口间可沿用。不能把 Serve 和 Funnel 同时配置在同一端口，因此使用 8443 与 443 区分。已有其他程序占用这两个端口时脚本停止；配置失败时回退本次新建的入口，不重置其他 Tailscale 服务。脚本不会绕过 Tailscale 官方的启用步骤。

Funnel 目前处于 Beta，并有不可自行调整的带宽限制，实际实时消息与图片传输需要从外部设备测试。详见 [Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel)。电脑、Codex、Relay 和 Tailscale 均需持续运行。

## 连接多台设备

一个已配对的手机浏览器可以查看多台执行机，选择各自的项目和对话；每条对话绑定它原来的执行设备。两台电脑需要各自运行 Runner，并使用不同的 `CODEX_RELAY_DEVICE_ID`，统一连接同一个 Relay。需要继续原桌面对话时，每台电脑还需准备并通过自己的原生桌面入口启动 Codex。

每台执行机只需要运行一个 Runner。先在 Relay 所在电脑设置一个固定 token，并让 Relay 监听一个可以被其他设备访问的地址：

```powershell
$env:CODEX_RELAY_TOKEN = "换成一段随机长字符串"
$env:HOST = "0.0.0.0"
npm start
```

在另一台电脑上复制本项目源码，保留模块目录结构；不要复制 `.relay-data`，其中包含第一台电脑的配对记录和原生连接凭据。设置相同 Runner token 和 Relay 地址（手机配对码不能用作 Runner token）：

```powershell
$env:CODEX_RELAY_SERVER = "http://你的内网地址:4317"
$env:CODEX_RELAY_TOKEN = "换成同一段随机长字符串"
$env:CODEX_RELAY_DEVICE_ID = "office-pc"
$env:CODEX_RELAY_DEVICE_NAME = "办公室电脑"
$env:CODEX_RELAY_CWD = "D:\\Project"
npm run runner
```

Runner 是出站连接，所以执行机不需要开放入站端口。浏览器使用电脑生成的配对码连接；外网浏览器可使用上面的 Tailscale 私有 HTTPS 入口，远程 Runner 的网络与共享 token 则需要单独配置。

混合模式的连接检查直接查询公网 DNS，并逐条检查 Funnel 公网地址的 HTTPS 和配对保护；不会把 Tailscale 内网访问成功当作外网正常。部分公网线路失败会显示警告，全部失败显示错误。本机的“恢复连接”会核对配置后重新连接原来的 443 Funnel，保留 8443 私有入口、原网址和当前桌面任务。

## 可选配置

- `PORT`：Relay 端口，默认 `4317`。
- `HOST`：监听地址，默认 `127.0.0.1`。
- `HOST`：默认 `127.0.0.1`。通常使用本机网页的局域网开关；手动设为 `0.0.0.0` 会绕过该开关的监听范围，需要自行管理防火墙。
- `CODEX_RELAY_EXTERNAL_URL`：可覆盖保存的私有 HTTPS 入口；只接受精确的 `https://设备名.私有网络名.ts.net` 根地址。
- `CODEX_RELAY_TOKEN`：Runner 与 Relay 之间的共享 token；不设置时随机生成并保存在 `.relay-data/runner-token`，重启后保持一致。
- `CODEX_WORKSPACE`：本机 Runner 的默认工作目录。
- `CODEX_BIN`：Codex 可执行文件路径；找不到 `codex` 命令时使用。

## 协议边界

Runner 使用 Codex app-server 的 stdio JSONL 协议，把 JSON-RPC 请求和通知转发到 Relay。Relay 创建的任务直接接收 app-server 事件。

新版分页 Desktop 对话读取 app-server 当前可见的回合列表，默认只加载最近 5 个回合的完整内容，较早回合仅读取编号和状态用于计数；展开后按需读取详细内容。旧版对话继续通过本机 `.codex/sessions` 追加读取原生 `item_completed` 条目，保持 UTF-8 和未写完的行完整。两种历史都区分 `commentary` 与 `final_answer`，不把底层工具调用外壳当成命令。工具输出过大时会明确截断内容，不会丢弃条目。分页协议未提供未加载条目的总数时，消息总数不显示估算值。

文件监听有 300ms 合并窗口；每 15 秒检查线程列表以发现新对话，每 10 秒检查文件大小以补偿遗漏的文件通知。原生连接已更新时，实时事件按到达顺序以 50ms 窗口合并，经 SSE 推送浏览器；历史负责补齐较早内容和连接断开期间的记录。历史文件尚未追上实时输出时保留当前条目，避免旧快照覆盖输出或重复追加文本。相同内容不发布更新，浏览器保留原有 DOM 节点并只更新变化部分。

新的用户消息出现时，浏览器将它定位到对话区域上方一次。后续回复、工具执行和状态更新保留当前阅读位置，即使当前位置接近底部也不会自动追随输出。切换对话会记住本页内的阅读位置；返回时若出现了新的用户输入，则定位到新输入。最新回合预留一屏空间，使短消息和结束后的折叠不会把用户消息挤回底部。桌面续聊的输入来源与压缩后上下文保留差异仍待定位，证据和边界见 [待定位问题](docs/KNOWN-ISSUES.md)。

外网加载时，界面模块提前并行加载，初始授权、设备、项目和对话列表合并为一次请求；实时连接与当前对话历史同时建立。每个浏览器只下载自己展开的回合，默认最近 5 个，较早消息和总数仍保留，点击后再取。文本响应按浏览器支持使用 Brotli 或 gzip 压缩，界面文件使用 ETag 校验缓存；对话接口保持 `no-store`，实时事件流不缓冲、不压缩。相同历史版本和展开范围不会重复下载。

对话列表用黄色点表示运行中（包括等待回答、审批），蓝色点表示结束后未读。已读记录保存在 `.relay-data/session-read-state.json`，在 Relay 的手机和电脑间共享。远程网页独立管理已读状态，不读取或修改 Codex 桌面端的已读记录，也不等待桌面确认。网页在前台加载当前完成回复并滚到最新位置后保存已读；点击“下一个处理”打开未读回复时，定位并加载完当前回复即可保存。后台预加载不会标记其他对话已读。保存时核对完成标记，过期回执不会清除新回复的未读状态。完成标记使用稳定回合编号，旧格式自动迁移；迁移保留 Relay 自己的已读记录，移除桌面覆盖，避免旧对话重新变成未读。时间精度改变和历史重新加载不会把同一条回复变成未读。

对话上方的“Codex 当前”读取 Codex 的 `turn_context` / `thread_settings_applied` 或成功的 app-server 响应，显示已确认的模型与推理强度。它与输入区下次发送的选择分开；尚未记录的强度明确显示“尚未确认”，不使用模型列表的默认值推测。只变更设置时发布轻量元数据，不重复下载历史。

当前回合直接显示重连次数、等待网络、收到的上下文压缩开始/完成事件及错误。桌面没有写入 rollout 的重连次数通过只读的 `logs_*.sqlite` 线程诊断补齐，监听 WAL 变化，按线程和回合匹配，不读取隐藏项目的历史。每次重连记录保留在上方的折叠消息里；收到新输出或回合结束后，停止显示旧的重连状态。回复上方的“已处理”从本次用户输入开始计时，收到新状态、重连或压缩时继续累计，结束后固定为“用时”；每秒只更新计时文字，不重绘对话。桌面未持久化的压缩开始或全局网络提示无法从历史恢复；这时显示最后已确认的活动，避免猜测。

连续执行记录在运行中也默认折叠，摘要显示实际执行的命令条数；过程记录、网络重连、命令输出不计入命令数量，展开后按原顺序显示。只有过程记录而没有命令时显示“过程记录”。普通回复与提问单独展示，图片单独折叠；实时活动和错误仍可直接看到。新记录到达时保留手动展开状态，大列表展开后仍分批显示。已完成、已中断或失败回合的中间回复一并收入历史区，外面只保留最终结果和错误提示；最终回复到达时立即折叠过程，即使运行状态更新稍晚也不再保留过程展开。历史汇总分别计算消息数和命令数，不把过程记录算作消息或命令。

中断、重连或重试后，没有新的用户消息的续跑段合并为同一显示回合，共用一个历史折叠条。消息数与实际命令数累计，用时累加各段执行时长，不计段间暂停时间；当前状态、可回答的问题和最终结果以最后一段为准。新的用户消息开始下一显示回合，原始记录及其回合编号保持不变。分页提示只显示实际可见的合并回合数，避免把内部执行段总数当作用户提问次数。

输入框的「Skill / @」可以选择当前项目的技能、引用同一电脑的其他对话、搜索项目文件或选择已启用的应用；输入 `$` 或 `@` 也可打开选择器。已选项目作为标签显示，随当前对话草稿保存，并随发送、排队、引导和撤回保留。Skill 使用原生 `skill` 输入，应用使用 `app://` 原生引用；文件提供路径，对话提供最近最多 6 条、每条最多 3000 字符的摘录。摘录是参考资料，不是引用对话的全部历史。最多同时选择 8 项；引用列表在打开时读取，图片不随引用自动下载。

当前对话已有目标时，输入框上方固定显示与输入框同宽的目标条，包含目标状态、最多 32 字的摘要和桌面记录的累计用时，箭头展开完整内容与用量，点击“管理目标”进入原有目标面板。仅当前打开的对话每 15 秒读取一次目标；后台、离线时暂停，目标编辑面板打开时复用面板的刷新，切换对话立即清除旧目标。累计用时直接显示桌面采样值，不用回合时间推算。支持目标接口的原生连接可设置、暂停、继续或移除目标，操作携带明确的用户来源；暂停只控制后续目标续跑，不等同于中断当前回合。旧的运行中代理未开放目标控制时，面板只读，不通过其他执行器冒充原桌面的目标操作。下次正常打开使用新版代理的桌面后，目标控制会按连接能力自动启用；本功能不要求立即重启桌面。

输入框显示选中的模型与推理强度；闪电单独控制 Fast。模型列表提供实际速度档位与说明，Runner 通过 `serviceTier` 将选择传给 app-server，关闭 Fast 则显式恢复标准速度。桌面原生连接下可以在网页选择只读、工作区访问或完全访问，随下一条新回合的 `turn/start` 生效；排队消息保留所选权限，运行中追加不会修改当前回合权限。界面用“下次”标示尚未确认的权限，实际权限仍以桌面写入的上下文为准；选择“沿用当前权限”不发送权限覆盖。打开对话时先跟随它的当前权限，避免重用以前的选择。设备配置限制继续校验；旧的插件转发连接不支持切换权限。原生连接正常时，Fast 也可在网页为当前对话单独选择，随下一条新回合生效；当前回合的引导不会改变速度档位。连接断开时开关禁用，旧插件转发连接仍沿用桌面设置。

## 验证

手机可从侧栏底部「添加到手机桌面」查看安装入口。支持安装的浏览器使用独立窗口；鸿蒙浏览器可能只创建网页快捷方式，实际显示方式以手机为准。支持全屏的浏览器也提供手动全屏按钮。应用更新先保存草稿，再由用户点击更新，不会在输入时自动刷新。

侧栏底部始终提供「检查更新」，发现新版后改为「有新版 · 更新页面」；点击才会保存草稿、启用新版页面缓存并刷新。回到前台或网络恢复时可自动检查，自动检查至少间隔一分钟，不定时轮询；检查失败不清理现有页面、授权和草稿。另一个窗口先完成更新时，本窗口仍提示刷新。旧版应用没有这个按钮时，可在同一电脑网址的 `/update.html` 手动检查并更新，然后关闭并重新打开桌面应用；无需卸载或重新配对。更新网页不重启 Relay 或 Codex。

手机需要分别连接两台独立电脑时，在浏览器分别打开两台电脑各自的地址，各安装一次。先在侧栏「设备」保存电脑名称，安装清单使用「Codex · 电脑名称」；尚未命名则使用运行服务的电脑主机名。每个地址保留独立的应用身份，修改电脑名称不改变身份；安装清单不使用离线页面缓存，避免改名后继续提供旧名称。已安装图标何时改名由手机浏览器决定。

快速启动只缓存公共界面文件。浏览器本机最多保存 5 条最近对话的有限文字预览（每条最多 16 条消息，总计约 1 MiB），不保存命令输出或图片文件；超过 7 天不再恢复，下次打开时清除。重新打开先显示保存的文字和草稿，联网后核对最新内容；核对前明确标注「状态待核对」并禁用发送。确认授权失效时清除文字预览，也可在安装窗口手动清除。此预览仅供当前浏览器恢复，不替代服务端历史。

手机输入框默认保持紧凑，不必等到键盘弹起才缩小；「⋯」打开技能、目标和权限，模型、附件和发送直接可见。目标条默认单行，展开后查看完整目标和累计时间；输入框右上角可手动展开。阅读历史期间新输出保留当前位置，通过输入框右上角的向下箭头回到最新，亮点表示有新内容，按钮不覆盖正文；主动回到最新后跟随后续输出，向上阅读则停止跟随。连接提示区分浏览器连接、执行设备和桌面接管状态，连接检查显示检查时间与检测位置。后台提醒需单独开启并在手机上测试送达。「添加到手机桌面」入口仍在左侧栏底部。

运行 `npm test` 检查原生条目解析、完整回合与计数、追加读取、输出更新、SSE 去重，以及项目目录、权限和桌面占用时的原线程续聊。原生控制集成测试使用隔离服务器、Runner 与模拟桌面核心，验证运行中追加、中断、真实提问/审批回复、过期与同时回答、实时输出不被旧历史覆盖，不提交模型请求。`tests/dom-sync.browser.html` 是浏览器回归测试页面；复制到 `public/_dom-sync-test.html` 后访问它，验证零 DOM 修改、嵌套展开状态、焦点和节点身份保留，验证后删除该临时副本。

`node tests/runner-smoke.mjs` 是可选的真实发送验证：在临时目录和不落盘的只读线程中发送一张测试图，检查实际模型、权限和图像识别回复。它会消耗一次小型模型请求，不属于默认测试；`RELAY_SMOKE_MODEL` 可指定模型。

`node tests/native-desktop-preflight.mjs <已有线程ID>` 是可选的真实 CLI 只读预检。它使用临时启动器与连接记录，检查协议必要字段、初始化、认证管道和原会话读取，不提交模型请求、不恢复写入连接，也不切换当前桌面。实际桌面需要先完成 `npm run connect:desktop` 的入口准备；手机发送与压缩后的续聊仍需另外验证。

`tests/timeline-scroll.browser.html` 使用实际样式和 DOM 同步模块验证新输入定位、连续输出保持位置、手动滚动、展开历史及回合结束折叠。临时复制到 `public/_timeline-scroll-test.html` 后访问，测试只生成页面内的模拟消息，不提交真实 Codex 请求；验证后删除该临时副本。

历史累计 token 用量显示在左下角，点击打开独立统计窗口，查看各模型的累计、占比和输入／缓存输入／输出／推理明细。右上角只显示额度余量，额度与上下文窗口不再混入历史模型明细。统计本机 Codex 的 sessions 与 archived_sessions，只读取计数和模型记录；后台工作线程维护 `.relay-data/usage-history.sqlite`，首次建立索引后仅扫描新增内容，未发送完整历史到网页。复制的分支记录按原始用量事件去重，不累加继承的累计计数；缓存输入包含在输入内，推理包含在输出内。统计范围是本机保存的调用记录，不代表其他电脑或已删除日志的账号账单。网页可见时约每分钟增量刷新，已保存的统计通过 Relay 在所有网页共享。

历史统计窗口默认显示最近一个月（含今天的最近 30 天），可切换最近一周（含今天的最近 7 天）、今日、全部历史或自定义起止日期。总 token、模型占比和各项明细一起按时间筛选，左下角的累计数始终显示全部历史。日期按访问网页设备的本地时区计算，开始日期包含当天零点，结束日期包含整天；后端通过现有索引的时间字段查询，不重新扫描聊天原文，仅返回各模型的汇总。网页缓存最近查询，同一时间段在后台索引更新后重新查询。

需要载入新版后台接口时，可双击 `更新Relay后台.cmd`，该入口只检查和更新 Relay 服务，不打开或重启 Codex 桌面。有 Relay 执行中的任务或待回答／待审批请求时会保留后台，提示先处理这些任务。更新完成后刷新网页。

token/s 显示在输入框下方、上下文百分比左侧；手机上这两项独占一行，避免挤压模型选择与发送按钮。使用同一对话回合、同一模型的两次输出计数报告计算区间平均；不足两次报告时显示历史可测区间的采样均速，无可用样本显示“—”。输入框明确区分“任务均速”和回退的“历史均速”；包含思考、工具执行、重试和等待，并非逐 token 解码速度。当前接口没有提供模型生成速率，不能把任务均速当作模型实际吐字速度；可点击查看说明。

HTML 预览支持 Markdown 本地链接（含目录括号）和原生 `visualize` 卡片。普通 HTML 入口保持静态模式；“交互预览”按需执行内嵌脚本，用于自包含 Canvas／SVG 动画。交互页面采用无同源权限的 sandbox，禁止网络请求、外部脚本、弹窗和表单提交，因此不访问 Relay API、登录状态或浏览器存储；依赖外部 JS／资源的页面需要改为自包含文件后预览。

管理应用“启动与服务 → 打开账号切换”可接入桌面 `Codex/codex-switch.ps1` 工具。首次接入只备份和修改工具代码，不复制、读取或上传账号快照；原 `switch.bat` 继续可用。切换由用户在账号窗口中确认，关闭范围限官方 Codex GUI，保留 Relay、Runner 和其他 CLI。切换后使用当前安装包身份和原生代理启动，验证新接管连接，失败不会退回普通 EXE。安装版适配入口每次读取 current.json，因此 OTA 后不保留旧版本路径。切换账号仍会中断桌面任务，不能跨账号无缝接续正在执行的回合。

对话行右侧的图钉可以置顶、取消置顶。置顶仍在原项目内，按置顶先后保持顺序，普通对话继续按最近活动排序；记录在服务端 preferences.json，多个网页共享。置顶对话不会因“只显示最近5条”被隐藏。不增加对话改名，也不修改 Codex 桌面的置顶记录。

侧栏搜索框旁的“提醒设置”提供独立的后台提醒开关。支持标准 Web Push 的浏览器在用户允许通知后可以订阅；未提供 PushManager 的设备明确提示能力不可用，安装网页应用本身不代表支持锁屏提醒。“10秒后测试”仅安排一次测试，实际锁屏送达须由手机确认。后台只对新的完成、待回答、待审批、失败、中断发通知，不因发送消息提醒，不重播已见历史；通知不携带对话标题、正文或图片。

Web Push 使用本机保存的 VAPID 密钥和加密订阅，密钥与订阅不进入安装包，订阅随浏览器配对授权过期或撤销停止。默认接入 Google、Apple、Mozilla、Microsoft 的标准推送端点，其他端点明确提示尚未适配，不接受任意 URL 转发。失效订阅（404/410）自动清理，通知失败不影响聊天。关闭本设备后台提醒时取消浏览器订阅。每台执行电脑独立管理自己的提醒，服务端或厂商推送链路不可用时不保证送达。

手机桌面图标按电脑名称自动区分：台式机使用蓝色“台”，笔记本使用紫色“笔”，家里与办公室分别有绿色“家”、橙色“办”；也可在「设备 → 手机桌面图标」手动选择六种样式。样式保存在服务端，修改样式不改变应用身份。安装清单、Apple 桌面入口、网页图标与后台提醒使用同一电脑的图标；图标地址带内容版本，独立于通用页面缓存。已安装图标的实际更新由浏览器或手机系统管理，网页更新按钮不保证立即替换桌面启动器图标。
